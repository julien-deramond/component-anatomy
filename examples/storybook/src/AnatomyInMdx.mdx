# Anatomy in MDX

`@component-anatomy/storybook/blocks` exports one block:

```jsx
import { Anatomy } from '@component-anatomy/storybook/blocks';

<Anatomy of={ButtonStories.Anatomy} />
```

It renders the addon panel's table inline, wired to the story you point it at.
The addon panel itself is unchanged — it still shows in story view for every
story in this Storybook.

## Several components on one page

Each block talks only to the story it names. Hovering a row below highlights
parts in *that* canvas and no other, even though three independent anatomies
share this page.

### Slider

<Canvas of={SliderStories.Anatomy} />

<Anatomy of={SliderStories.Anatomy} />

### Tabs — auto-discovered

`Tabs.AutoDiscovered` sets `parameters.anatomy = {}` and lists no parts. The
part list is read from the `data-part` attributes of the story as it renders,
and reaches this block over the addon channel — so auto-discovery works in MDX
too, as long as the story is on the page.

<Canvas of={TabsStories.AutoDiscovered} />

<Anatomy of={TabsStories.AutoDiscovered} />

### Tabs — high contrast

<Canvas of={TabsStories.HighContrast} />

<Anatomy of={TabsStories.HighContrast} />

## Pointing at a meta

Pass the whole CSF module to document the component rather than one story. The
meta's `parameters.anatomy` is used; there is no canvas to discover parts from
or to sync hover with, so this form needs an explicit `parts` list. `Button`'s
meta sets no `anatomy` parameter, so the block below says what is missing
rather than rendering nothing:

```jsx
<Anatomy of={ButtonStories} />
```

<Anatomy of={ButtonStories} />

## A curated subset

`parts` overrides both `parameters.anatomy.parts` and auto-discovery, for when
prose needs to focus on two rows out of ten. Hover sync still works.

<Canvas of={ButtonStories.Anatomy} />

<Anatomy
  of={ButtonStories.Anatomy}
  parts={[
    { id: 'icon', name: 'Icon', description: 'The only part this section is about.' },
  ]}
/>

## Static table

`sync={false}` drops the channel wiring entirely — no hover sync, no
auto-discovery, just the rows.

<Anatomy of={SliderStories.Anatomy} sync={false} />

## When there is nothing to show

Three stories in **Edge cases → Empty states** cover the states a real Storybook runs into.
Each renders here exactly as it does in the addon panel — the block and the
panel share the same component.

### No parts

`Edge cases → Empty states → No Parts` asks for auto-discovery with `anatomy: {}`, but nothing
in its markup carries a `data-part` attribute. Rather than an empty list, both
surfaces explain what to add.

<Canvas of={EdgeCaseStories.NoParts} />

<Anatomy of={EdgeCaseStories.NoParts} />

### Disabled for a story

`anatomy: { disable: true }` turns the addon off for one story — no overlays,
no controller over the canvas. Its `parts` are still declared, and are
deliberately not rendered.

In story view you never see this message: Storybook drops the whole **Anatomy**
tab for a story whose `anatomy` parameter is disabled, which is its own
behaviour for every addon panel. A docs page has no tab to drop, so the block
says it instead.

<Canvas of={EdgeCaseStories.Disabled} />

<Anatomy of={EdgeCaseStories.Disabled} />

### Not configured

A story with no `anatomy` parameter at all. Its canvas *is* annotated, so
`anatomy: {}` is all it would take.

<Canvas of={EdgeCaseStories.NotConfigured} />

<Anatomy of={EdgeCaseStories.NotConfigured} />

Passing `parts` explicitly overrides all three: the block renders the list you
give it whatever the story's parameters say.

<Anatomy
  of={EdgeCaseStories.NotConfigured}
  parts={[{ id: 'label', name: 'Label', description: 'Curated here, not in the story.' }]}
/>
